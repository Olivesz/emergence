# Acts VI and VIII in full

The README keeps each act to a line or two. These two do more than one thing,
so here is the long version.

## Act VI — The Slime Mold (Physarum)

The brainless yellow slime mold *Physarum polycephalum* — which famously reproduced the Tokyo rail network and solves mazes. Thousands of particle-agents each sniff a chemical trail at three points ahead, steer toward the strongest, move, and deposit; the trail diffuses and evaporates. **Reinforced routes survive, dead ends fade** — the emergent network *is* the solution. "Connect the cities" and "Free veins" run the agent model; **"Solve a maze"** grows the organism outward from a single **start** life-point through a huge world-filling labyrinth and, the instant it reaches the **end**, reveals the shortest connecting path (deterministic breadth-first — always the true shortest route); **"Flow physics"** runs the *actual organism physics* — the **Tero flow-conductivity model** on a braided maze: current is injected at the start and drained at the end (Kirchhoff), flux follows Poiseuille's law through each tube, and every tube adapts `D += δ·(|Q|^μ − D)` (μ≈1.8, superlinear) so tubes carrying flux **thicken** and the rest **starve** — the faithful model from [robert-30/physarum-maze](https://github.com/robert-30/physarum-maze): each *maze cell* is a graph node (~200 nodes), the Kirchhoff pressure system is solved with a current source each iteration. It **forages**: the slime starts at the source **only** (no prior knowledge of the maze), grows its frontier outward exploring the corridors, **peels dead-ends as it goes** (a tip that can't advance retracts and is never re-explored), and the instant its frontier reaches the goal it stops exploring and the flux concentrates — `D += δ·(|Q|^μ − D)`, μ≈1.8 — onto the shortest connecting tube while the rest starve. Rendered as **thick glowing veins** (width ∝ conductivity) over the maze: a dim network shows where it explored, a bright thick tube is the solution. **"Smart solve"** is the *efficient* counterpart — **bidirectional A\***: two frontiers grow from the two foods, each guided toward the other by `f = cost-so-far + straight-line-distance`, meeting in the middle. On a hard, heavily-braided maze with **random, non-corner endpoints** (so the solution isn't a diagonal) it finds the shortest path exploring only ~10% of the cells — the live **Explored** readout shows the cost. The solvers run in **slow-motion** (speed slider) so you can watch the frontiers explore. Note the theory: **"Smart solve"** assumes you *know* the goal (heuristic → A\*); **"Solve a maze"** does *not* (uninformed) and so must expand its frontier uniformly by distance — the provably-optimal shortest-path search when the goal's location is unknown. The gap in *Explored* between them is exactly the value of knowing where you're going. **"No-map walk"** is the true *stuck-inside-with-no-map* solver — **Trémaux's algorithm**: one agent with only local sensing marks each passage as it walks it, never takes a twice-marked passage, and backtracks from dead-ends; it's guaranteed to escape *any* maze, and the passages walked once trace the solution. "Slime maze" is the pure agent-model companion.

The model behind "Solve a maze" and "Flow physics" is described in
[physarum.md](physarum.md).

## Act VIII — Logic Gates → a Computer (Wireworld)

A 4-state CA **designed to be a computer**: empty, electron head, electron tail, conductor — with the single rule "a conductor becomes a head iff exactly 1 or 2 neighbours are heads." Electrons run one cell per tick along wires (the tail behind stops backflow, so wires are directional), and where wires meet, that threshold rule *is* logic. This act climbs the whole stack of a machine: a **clock** (an electron circling a loop forever); a **wire**; a simulation-**verified OR** (00→0,01→1,10→1,11→1) and **XOR** (…11→**0**) gate — both computing their truth tables live by auto-cycling inputs. XOR is the subtle one: A drives *two* of the output junction's diagonal corners (2 heads), B drives a third (1 head), and when *both* fire, three heads coincide and the "not 3" rule **suppresses** the output. Because that rule can never require ≥2 heads, a naive AND is impossible — so this act builds a verified **AND** as the two-stage **`(A OR B) − (A XOR B)`**, dissolving the notorious Wireworld **crossover** by tapping the OR *locally* where the XOR already brings the inputs together, with a searched-for **diode** on each input to block junction backflow. From AND + XOR comes a **half-adder** — one circuit emitting both **sum** (A⊕B) and **carry** (A·B), i.e. binary addition (`1+1 → sum 0, carry 1`). And **Memory**: a bit *stored* as an electron circling a loop forever (present=1), read non-destructively by a tap — the leap from logic to **state**. Logic, arithmetic, and memory — the three things a CPU is made of — then compose into an actual **[processor](cpu/)**: a working **SAP-1** CPU (bus, program counter, RAM, instruction register, accumulator, ALU, and a ring-counter control unit) expressed as one synchronous netlist of **NAND gates** and **D flip-flops** — 1446 and 175 of them. It runs real programs with loops and branches (`5+3`, countdown, Fibonacci-till-overflow), watchable live in an [interactive front panel](cpu/cpu.html), with a bigger **[SAP-2](cpu/)** (256 bytes, a stack, ~35 instructions) running multiply, primes, and bubble-sort. And for the *lowest* view of all, a companion drops a level beneath Wireworld into raw **[Conway's Life](glider-logic/)**, where there is no wire or clock at all — a glider is the signal, a glider gun the source, and **logic gates are literally glider collisions** (NOT, AND, XOR, NAND, all verified). Those compose into a **half-adder and full-adder** — real binary arithmetic in colliding gliders (`3+2 → 101 = 5`, every bit checked against the raw rule, with each column's carry handed to the next in Python) — and, with the canonical **Snark reflector** and **glider duplicator** verified in-engine, the real routing hardware to turn and fan out a signal — from which comes a **physically-routed AND gate**: input B turned through *two* reflectors onto the merge, output escaping on a virgin lane, its truth table exact and tick-perfect in the raw rule. Watch it run in a zoomable **[whole-circuit viewer](glider-logic/life-viewer.html)**. All of it emerged from "fire on 1 or 2 neighbours."

The gates' truth tables are checked from the page itself by
`cpu/test_toy_gates.py`; the CPU and the compiler are described in
[`cpu/README.md`](../cpu/README.md).
